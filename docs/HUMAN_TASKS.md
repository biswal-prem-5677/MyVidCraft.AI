# Things Only You Can Do

Everything in this repository that can be done without you has been done. This
file is the remainder — the tasks that need a human, a credit card, a browser
login, or a judgment call about your own reputation.

**How to use this file.** Work top to bottom. §1 is the only thing blocking the
project *right now*; §2 unlocks more automation; §3 and §4 are deliberately
parked until §1 is answered, and parking them is a decision, not an oversight.
Each task says what it blocks and why nobody else can do it.

**Status:** last reconciled 2026-08-01 against `main`. Test suite green
(311 passed, 2 skipped by design). Nothing is committed-but-unpushed.

## 1. Blocking everything — the Gate 1 listen test

> ### Play this file and answer one question.
>
> ```
> data/artifacts/6d038b2c-9282-4911-bd03-6460018631bf/episode.wav
> ```
>
> **Would you publish this under your own name?**

That is the entire task. It takes six minutes.

**Why only you.** It is a judgment about *your* reputation and *your* taste. A
machine can verify the file is six minutes of two-voice speech at the right
sample rate with no silent holes — and it has, all of that passed — but it
cannot decide whether the result is something you would attach your name to.
That is the one thing the gate is actually asking.

**Before you judge it, two things that are not defects:**

1. **It will sound quiet.** −19.2 LUFS, about 3 LU under the podcast norm.
   `workers/media/audio/normalize.py` does RMS normalisation to −20 dBFS and
   documents that it deliberately is not EBU R128. Turn it up; judge the voice,
   not the level.
2. **The script is real.** It was generated by `claude-opus-5`, not the template
   fallback, so you are judging the actual product and not a stub.

**What it blocks:** Gates 2, 3 and 4 — auth, billing, storage, clips.
Everything. This is by design (rule R2), because if the answer is *no*, all of
that work is wasted, and the rules you wrote say **stop** rather than push
through. One week spent learning this beats six months.

**When you have an answer:**

| Answer | Do this |
|---|---|
| **Yes** | Record it in `docs/EXECUTION_RULES.md` §7, then §2 and §3 of this file open up. |
| **No** | Stop. Do not start Gate 2. Write down *what specifically* fell short — voice, script, pacing, or mix — because that determines whether this is fixable with a better TTS vendor or is a product-level dead end. |

A *no* is a legitimate, useful outcome. The gate exists to make stopping
possible.

## 2. Small tasks that unlock more automation

These are quick, and each one removes a permanent blind spot. Worth doing even
before the listen test, because they cost minutes and pay back every session.

### 2.1 Confirm CI is actually green

**Why only you.** The repo is private and this machine has no GitHub
credentials, so the Actions tab cannot be read from here.

**Steps:**

1. Open <https://github.com/biswal-prem-5677/MyVidCraft.AI/actions>
2. Check the latest run on `main` is green.
3. If red, paste the failing job's log back here and it gets fixed.

**What it blocks:** a Gate 1 success criterion is currently recorded as
`⏳ unverified` purely because nobody has looked. It may well already be green.

### 2.2 Install the GitHub CLI (optional, 2 minutes)

```powershell
winget install GitHub.cli
gh auth login
```

**Why it is worth it.** After this, CI status, workflow logs, PRs and issues can
all be checked and fixed without you relaying anything. This is the single
highest-leverage two minutes on the list.

### 2.3 Install Docker Desktop

**Why only you.** It needs an installer, a reboot, and on Windows a WSL2 backend
— all local admin actions.

**Steps:**

```powershell
winget install Docker.DockerDesktop
# reboot, start Docker Desktop, wait for the whale icon to settle
```

Then, from the repo root:

```bash
export MYVIDCRAFT_TTS_ENGINE=edge     # free, no account
docker compose up --build -d
python scripts/verify_gate1.py
```

`scripts/verify_gate1.py` was written for exactly this and has already been
run successfully against a live stack, so it is not being tried for the first
time on your machine. It checks health, renders a full episode, verifies the
artifacts, confirms the audio is neither silent nor truncated, and saves the WAV
for you to listen to. It prints `RESULT:` and exits non-zero on any failure.

To re-check without paying for another episode:
`python scripts/verify_gate1.py --run-id <id>`

**What it blocks:** the Gate 1 criterion *"`docker compose up` on Linux produces
a complete episode"*. CI already builds both images and boots them, so this is
narrower than it sounds — it verifies that a **rendered episode** comes out of
the container, which CI does not check.

**Deliberate:** yes. The compose stack was written and is believed correct, but
it is recorded as `⏳ unverified` rather than assumed working, per rule R5.

## 6. Known gaps that are NOT waiting on you

Listed so this file is not mistaken for the complete defect list. These need no
account, no card and no decision — they are ordinary work, correctly sequenced
behind the gate, and they will get done when their gate opens.

| Gap | Gate | Note |
|---|---|---|
| No auth or ownership on any endpoint | 2 | The single largest security hole. **This is why the README says do not expose it to the internet.** |
| No rate limiting | 2 | No auth + no limits + LLM calls = anyone who finds the URL can burn your Anthropic budget. |
| Artifacts stored on local disk | 2 | Lost on container restart. Needs 3.3. |
| Run history exists in the API, ignored by the UI | 2 | `GET /runs` works; the UI never calls it. Cheapest high-value UI fix available. |
| Brand profile is a raw JSON textarea | 2 | A developer console, not a product. |
| No metrics table — cost/latency per stage | 3 | You cannot price what you cannot measure. |
| Opus is the default model | 3 | Switching the default to Sonnet/Haiku is roughly a 10× cost reduction. |
| No `llm` vs `template` provenance surfaced | 3 | Today a run can silently return generic filler and look identical to a real one. |
| Captions cannot render non-Latin scripts | 4 | `raster.py` is a hand-written 5×7 ASCII bitmap font. Cited in the rules as the precedent for *don't hand-roll commodities*. |
| No monitoring, tracing, backups, or DR | 3+ | Standard operational gaps; all bought or configured, not built. |

`ENGINEERING_REVIEW.md` is the full independent assessment. Note that it was
written at commit `4ae5b5f` and two of its headline findings — the Windows-locked
TTS and the absence of Alembic migrations — have since been **fixed**. Its
security and product findings still stand.
